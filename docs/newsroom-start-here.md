# Start publishing and onboarding staff

Owner: jamesadebajo7@gmail.com. Open /admin on the deployed publication. Choose Forgot password to receive a one-use setup/recovery link; choose your own password. Do not share owner credentials with staff.

## Post a story

1. Create a contributor profile for the byline (Editorial → Contributors). This is public editorial information, separate from a staff login.
2. Open Articles → Create new. Set headline, slug, summary, body, section, format and bylines. Upload licensed imagery with alt text, credit and licence reference. An editor must confirm image rights.
3. Save Draft and use Preview to inspect the saved page.
4. Submit as Pending review. An editor saves Approved, then uses Publish as a separate action. A future publication time holds a first release until that time. Keep the original publication date when updating an already live story.
5. For an update, save the revision as a draft, repeat review/approval, then publish. Readers keep seeing the last published version while changes are being reviewed.

## Add people you hire

Administrators manage Users. Create a separate account for each colleague, using their real email, and link it to their Contributor profile. Writers can work on their own/assigned drafts and submit for review. Editors can review, confirm image rights and publish; they cannot create privileged accounts. Administrators manage accounts and newsroom configuration.

Use a random temporary password and privately ask the colleague to use Forgot password before signing in. Never reuse the founder password, publish temporary credentials, or give administrator access merely to write an article. If a colleague leaves, remove their account access; keep their public byline and published work as appropriate.

Publication scheduling currently covers first publication. Scheduling a revision of an already live article is deliberately rejected; publish the reviewed update when it is ready.
